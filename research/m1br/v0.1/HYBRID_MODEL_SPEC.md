# M1-BR｜混合译码模型规范 v0.1

**状态：Research Candidate / Not Human-Tested**  
**运行时原则：确定性；无大模型裁决**

## 1. 分层

```text
L0 排盘事实
L1 结构签名候选
L2 校准题回答
L3 混合裁决
L4 结果数据
L5 前台文案（本轮不写）
```

任何层级不得跳过中间层。传统术语不能直接进入前台人格结论，问题回答也不能静默改写排盘事实。

## 2. 四个结构签名

### SIG-A1｜输入条件 → 第一版

**研究对象：** 第一版形成前，输入、承接和输出是否构成连续路线。

必要状态：

- 有效输入或支持路线存在；
- 路线能够到达处理中心；
- 存在形成第一版的输出可能；
- 所依赖时间事实稳定。

关闭或降级：

- 关键输出被明确过滤；
- 只有输入，没有可达输出；
- 输入与输出属于不同对象；
- 时间候选改变路线。

该签名不等于聪明、敏感、谨慎或学习能力。

### SIG-A2｜成形判断 → 公开输出

**研究对象：** 已经成形的判断是否有公开、可观察且有承接的输出路线。

必要状态：

- 输出对象有效；
- 输出公开可见；
- 不是仅透出而无根、无承接；
- 未被同对象过滤状态关闭。

关闭或降级：

- 只有潜在或藏层输出；
- 可见但不可持续；
- 输出只存在于不稳定时间候选；
- 关键输出被关闭。

该签名不等于外向、口才、创意或表达天赋。

### SIG-B1｜权限/标准 → 可执行边界

**研究对象：** 自主判断、共同标准和责任角色能否在同一对象中形成可执行关系。

必要状态：

- 自主侧和外部标准侧均有效；
- 存在清楚的主次、中介或对象分离；
- 没有同对象、多重标准未解决状态；
- 所依赖时间事实稳定。

关闭或降级：

- 多套标准同对象且无主次；
- 名义上有解决，但路径无效；
- 只依靠“外部约束缺失”推断自主；
- 不同情境被误合并成一个全局状态。

该签名不等于成熟、高情商、领导力或难合作。

### SIG-C1｜输出对象 → 完成/后续承诺

**研究对象：** 可见输出是否进入明确完成对象，并进一步连接到责任或承诺接口。

必要状态：

- 输出能够到达明确资源、接收或完成对象；
- 完成对象不是名义存在；
- 后续责任接口有效时，能够形成连续路线；
- 资源竞争、过载或标准冲突未关闭该路线。

关闭或降级：

- 只有可见输出，没有接收对象；
- 完成对象存在但责任接口无效；
- 关键资源被竞争或负荷状态关闭；
- 输出、完成和责任属于不同对象。

该签名不等于商业能力、执行力、产品能力或责任感。

## 3. 修饰与守门

以下内容不能独立生成核心结果：

```text
MOD-CAPACITY    容量与支持
MOD-VISIBILITY  公开、潜在、可见但不稳定
MOD-LOAD        输出或资源负荷
MOD-CONFLICT    未解决冲突与解决状态
MOD-TIME        时间边界与候选盘稳定性
MOD-BRIDGE      接口桥接或组合状态
```

修饰只回答“何时出现、以何种强度出现、什么会关闭”，不回答“用户是什么人格”。

## 4. 命盘候选生成

每个签名只使用三档内部状态：

```text
supported   必要路线完整，关闭条件未命中
candidate   部分路线成立，但有一个未关闭的不确定点
absent      必要路线缺失或被明确关闭
```

不生成用户可见分数。

候选输出规则：

1. 最多输出三个候选；
2. `supported` 优先于 `candidate`；
3. 同一依赖簇中的近邻不得被当成两份独立人格证据；
4. 没有任何 `supported` 时，可以用两个 `candidate` 进入校准，但结果必须允许 `unresolved`；
5. 只有修饰而无签名候选时，不强行生成人格结果。

## 5. 校准后的裁决

校准题只在命盘候选之间分配现实路线证据。每道题最多支持一个候选、反向支持另一个候选，或记为不确定。

内部允许使用离散计数，不向用户展示：

```text
pair_support: -1 / 0 / +1
```

三题后：

- 同一候选获得一致支持，记为现实主路线；
- 两个候选各有支持，记为 `mixed`；
- 回答与命盘首候选相反但一致，记为 `adapted`；
- 回答矛盾或大量不确定，追加第四题；
- 第四题后仍无结果，记为 `unresolved`。

## 6. 四种结果关系

### aligned

命盘首候选与现实主路线一致。

### adapted

命盘候选仍存在，但用户现实中持续采用另一条候选路线。结果必须同时展示两层，不得说用户“答错”或命盘“失效”。

### mixed

两条路线分别在不同对象或情境成立。结果需指出区分条件，不能用“有时这样、有时那样”敷衍。

### unresolved

命盘候选、问题回答或时间边界不足以稳定裁决。结果应收缩，而不是补充更多泛化描述。

## 8. 版本变化

- 增删结构签名：major；
- 改必要条件或关闭条件：major；
- 改题槽、选题顺序或裁决门：minor；
- 只改最终文案、不改变机制：copy version；
- 测试开始后不得在同一版本中静默改变任何上述内容。
