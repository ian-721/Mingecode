# 04｜报告生成规范 v1.0 设计

## 1. 生成目标

报告不是“把所有能说的话都写进去”，而是从已冻结的核心规则证据包中选择有限、可追溯、可否认且与其他候选有区别的机制。

用户可见文本不展示四柱、十神、格局、权重、百分比、准确率或原型名。研究内部保留完整映射。

## 2. 输入契约

每份候选报告生成前必须具备：

```text
report_generation_version:
core_rule_set_version:
time_convention_version: civil_time_v1
source_register_version:
candidate_chart_count:
core_persona_candidate:
secondary_persona_candidate:
activated_rule_ids:
rejected_rule_ids_and_reasons:
evidence_families:
unresolved_conflicts:
time_sensitivity:
```

### 生成单一报告的硬门

- 至少两个独立证据家族支持同一核心机制；
- 至少一个锚点或两个支持规则；
- 没有同场景、同等级的未解决反向证据；
- 所有合理时间候选中核心机制稳定；
- 规则均来自冻结的 CRX 版本。

不满足时：主测试不生成单一核心报告；只能进入敏感性材料，输出双候选或“不足以确定”。

## 3. 八份母本的统一结构

每个候选原型一份母本，盲测版隐藏名称：

1. **运行方式**：判断中心、输入输出与启动方式；
2. **高光状态**：机制在适配情境下的资源；
3. **翻车方式**：同一机制过度使用或失去承接时的代价；
4. **常见误解**：别人看见的表面与真实机制差异；
5. **任务与决策场景**：至少一个可观察行为；
6. **关系与使用建议**：不做婚恋断言，只写边界、沟通或恢复策略。

## 4. 长度与比例

- 每份 320—380 个中文字；
- 同一四选一组最长与最短差不超过 8%；
- 6 个区块、段落数、标题长度和版式完全一致；
- 每份拆成 10 个“声明单元”：7 个资源/中性机制单元，3 个代价/限制单元；
- 每份至少 3 个具体、可被明确否认的行为声明；
- 每份至少 1 个适用条件和 1 个不适用/反向条件。

“七分正向、三分阴影”用声明单元计数，不靠编辑者主观感觉。

## 5. 可否认行为标准

合格声明必须包含情境和行为倾向，例如：

```text
面对没有明确标准的新任务，你更可能先做一个小试验，再决定是否投入完整流程。
```

不合格声明：

```text
你有时大胆，有时谨慎；你既希望被理解，也需要独处。
```

每个可否认声明在审计表中记录：

```text
claim_id:
report_master_id:
claim_text:
claim_type: resource | cost | misunderstanding | behavior | advice
context:
rule_ids:
evidence_families:
dimension:
counterevidence:
falsification_question:
```

## 6. 文案禁区

盲测母本中禁止：

- 领导、创业、精英、天赋、稀缺、强者、赢家、成功者；
- 富贵、贫穷、婚缘、克夫、克妻、疾病、灾祸、行运；
- “你注定”“天生就是”“绝不会”“一定能”；
- 原型名、命理术语、四柱信息和规则 ID；
- “虽然……但是……”式人人适用双面句堆叠；
- 用一个职业或生活方式代替人格机制；
- 把内部权重、统计门槛写成用户分数。

## 7. 两层输出

### 内部审计版

包含母本名称、Rule ID、Claim ID、证据家族、冲突与版本。

### 盲测清洁版

只包含六区块正文和统一研究说明；去除名称、图标、插画、颜色差异、传统术语和任何可识别元数据。

两层通过 `REPORT_CLAIM_MAP.md` 对应，但清洁版不能暴露映射。

## 8. 等质审计

每份报告必须横向检查：

| 项目 | 门槛 |
|---|---|
| 字数 | 320—380；同组差不超过 8% |
| 声明单元 | 10 个，7:3 |
| 可否认行为 | 至少 3 个 |
| 资源/代价 | 同量级，不把某原型写得明显更高级 |
| 语气 | 同一人称、肯定强度、自嘲程度 |
| 职业声望词 | 0 |
| 命理术语 | 0 |
| 原型名与视觉线索 | 0 |
| 建议 | 1 个具体策略，不用空泛鸡汤 |
| 阅读版式 | 字体、字号、行距、颜色、段距相同 |

横向审查时先遮住文件名和原型名，由审查者只判断哪份更正向、更具体、更体面。若能稳定指出某份“明显更好听”，材料退回重写。

## 9. 错配选择算法

每名未来参与者的三份错配类型固定：

1. **近邻错配**：六维模式距离最小，但核心原型不同；
2. **共享主维错配**：共享主维度，但次维度与翻车机制不同；
3. **远距等质错配**：机制距离较大，但长度、正向强度、具体性和职业声望相等。

### 约束

- 不按性别、职业、关系或研究者熟悉度挑错配；
- 不允许明显荒谬的反人格文本；
- 同一错配作为诱饵的总次数设上限；
- 距离并列时使用预注册 tie-break，不由研究者临场挑选；
- 实际错配必须来自同版本、同规范生成的匿名真实报告；本轮只用 FX 虚构夹具检查算法，不形成真实错配池；
- 错配身份在参与者作答前生成并封存。

建议距离只用于内部排序，不展示分数。距离字段可由六维定性等级、主机制、次机制和翻车机制共同构成；算法必须在真人数据进入前写定。

## 10. 巴纳姆与漂亮话控制

四选一排序后另呈现 6 个同长度段落：

- 2 个本人报告高区分段；
- 2 个预先写定的巴纳姆式双面陈述；
- 2 个通用漂亮话。

每段控制在相近长度和语气，随机呈现，不标来源。分别评价：

- 像我程度；
- 具体程度；
- 是否愿意分享。

控制段不替代真实错配，也不能按参与者调整。

## 11. 报告版本

```text
report_spec_version: 1.0.0
report_master_version: 0.1.0-draft -> 1.0.0-frozen
blind_text_version: 1.0.0
claim_map_version: 1.0.0
```

任何语义改变都必须更新版本、重新跑等质审计、重新选择错配并重新生成哈希。
