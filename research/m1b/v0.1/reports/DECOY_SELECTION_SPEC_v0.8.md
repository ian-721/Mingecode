# CRX-0.8｜四机制错配选择规范

**状态：** F1 Candidate / Not Executed  
**替代对象：** `DECOY_AND_CLAIM_SPEC_v1.0.md` 中依赖旧六维距离的部分  
**候选报告：** R01、R02、R03、R04  
**真人测试：** NOT AUTHORIZED

## 1. 目的

当前材料已从六维、八原型收束为四个对象机制。错配选择不得继续使用已否决的六维距离，也不得按职业、性别、熟悉程度或研究者印象挑选。

四份报告若保持当前版本，每名未来参与者的另外三份报告天然构成完整错配集；本规范只固定三份错配的角色和呈现约束，不筛掉任何一份。

## 2. 四机制对象

```text
R01 / M-A1：第一版形成前的输入条件与顺序
R02 / M-A2：判断成形后的公开外化与输出承接
R03 / M-B1：权限、标准、角色责任及主次
R04 / M-C1：接收对象、完成标准与后续承诺接口
```

显隐、容量、负荷、时间、桥接与关系状态只作守门或修饰，不增加错配距离维度。

## 3. 固定错配角色

| 本人报告 | 近邻错配 | 共享接口错配 | 远距错配 |
|---|---|---|---|
| R01 | R02 | R03 | R04 |
| R02 | R04 | R01 | R03 |
| R03 | R04 | R01 | R02 |
| R04 | R02 | R03 | R01 |

### 近邻定义

- R01/R02：同属输入—输出簇，差异在首版形成前与判断形成后；
- R02/R04：都可能出现版本/回应，差异在可见输出与完成/责任接口；
- R03/R04：都涉及标准与责任，差异在谁拍板与什么算完成。

### 共享接口定义

共享一个流程条件或接口词，但终点不同：

- R01/R03：都可能出现延迟，但分别因信息条件与权责主次；
- R02/R01：共享输入—输出端点；
- R04/R03：共享标准/责任词，但对象不同。

### 远距定义

当前定义级对象和流程位置最远的文本。远距并不允许写成明显荒谬或明显负面的反人格文本。

## 4. 呈现规则

- 四份必须来自同一 `REPORT_MASTER` 版本；
- 字体、长度、段落、标题、顺序和研究说明完全一致；
- A/B/C/D 位置按预生成随机化表分配；
- 不显示内部名称、机制编号、Rule ID 或错配角色；
- 每份在全样本中出现在 A/B/C/D 的次数尽量平衡；
- 不因参与者职业、关系、生活经历或研究者认识程度改变错配；
- 不允许研究者手工把“看起来最不像”的报告替换进来。

## 5. 合并后的失效规则

若独立遮名评审触发任何报告合并：

```text
R01 + R02 merge
R02 + R04 merge
R03 + R04 merge
```

则本规范立即失效，必须：

1. 升级报告版本；
2. 重建声明映射；
3. 重建错配角色；
4. 重算随机化表；
5. 重新执行等质与体面度审计；
6. 不得沿用旧 F1 候选哈希。

## 6. 并列与缺失处理

当前只有四份完整报告，不存在从大池中挑选的距离并列。未来若机制数增加：

1. 先按对象与流程位置分类；
2. 再按预注册的近邻层级排序；
3. 最后用固定 seed 解决同层并列；
4. 不允许人工临场挑选。

如果某参与者因时间或结构不稳定无法生成单一本人报告，则退出主样本，不用研究者指定“最像的一份”补齐。

## 7. 质量与声望门

错配规范只有在以下文件均通过时才可进入 F1：

```text
REPORT_EQUIVALENCE_AUDIT
PAIRWISE_DISCRIMINATION_MATRIX

```

若某份被独立评审判为明显更成熟、更会表达、更能交付或更负责，必须先修正文案或合并，不能靠错配算法抵消。
