# Batch 03｜压力接口、现实转化与桥接去重协议 v0.1

**状态：** F0 Draft / Process Test Only  
**适用规则：** `MC-R-021`—`MC-R-030`  
**合同：** `RULE_DEFINITION_CONTRACT_v1.2-draft.md`

## 1. 目的

Batch 03 最容易制造“精英人格”：制杀被写成强者，财链被写成创业与变现，官印被写成学历和体制优势，比劫争财被写成竞争本能。本协议把十条规则重构为对象特定的压力接口、资源路由、桥接、负荷与竞争状态，并设置依赖簇上限。

## 2. 压力—表达接口状态

### Axis PI-R｜压力响应子型

| 状态 | 规则 | 含义 | 核心释放 |
|---|---|---|---|
| `PI-R0 unknown` | — | 压力或响应通道未审查 | 否 |
| `PI-R1 methodical` | 021 | 关键食神直接处理有效压力 | pending_source |
| `PI-R2 reframing` | 022 | 关键伤官直接处理有效压力 | pending_source |
| `PI-R3 mixed` | 021+022 同等级 | 无法预注册主型 | 否 |

同一压力对象最多取一主型。不得把食神/伤官两条都算作两种优势。

### Axis PI-I｜表达—标准接口

| 状态 | 规则 | 含义 | 报告边界 |
|---|---|---|---|
| `PI-I0 unknown` | — | 是否直接相触未完成检查 | 不写 |
| `PI-I1 conflict_unresolved` | 023 | 同对象直接冲突且无救应 | pending_source 反向候选 |
| `PI-I2 bridge_resolved` | 024 | 伤官→财→官连续桥接 | modifier only |
| `PI-I3 context_split` | — | 不同对象/情境分别冲突与桥接 | 写情境分化，不做全局结论 |

023 与 024 对同一对象互斥。

## 3. 现实转化状态

### Axis RC-N｜资源节点

| 状态 | 规则 | 说明 |
|---|---|---|
| `RC-N0 unknown` | — | 资源节点未完成审查 |
| `RC-N1 public_supported` | 025 | 关键资源节点公开且有承接 |
| `RC-N2 overloaded` | 029 | 资源对象持续超过恢复容量 |
| `RC-N3 contested` | 030 | 同一关键资源对象被直接竞争 |

同一对象上 `public_supported` 不能与 `overloaded` 或 `contested` 同时正向释放。结构上可同时存在节点与风险，但报告只能采用风险修饰或关闭正向叙事。

### Axis RC-R｜路由

| 状态 | 规则 | 说明 | 独立性 |
|---|---|---|---|
| `RC-R1 output_to_resource` | 026 | 输出进入资源/完成接口 | pending_source |
| `RC-R2 resource_to_constraint` | 027 | 资源进入正式承诺 | pending_source |
| `RC-R3 full_bridge` | 024 | 伤官→财→官完整桥 | 组合修饰，不新增第三证据 |
| `RC-R4 constraint_to_support` | 028 | 官/杀→印→日主 | 跨簇桥接修饰 |

## 4. 簇上限

### `CL-PRESSURE-INTERFACE`

- 021/022 同一压力对象取一态；
- 023/024 同一接口未解决/已解决互斥；
- 021—024 复用输出与约束端点，同一对象最多一个正向簇贡献；
- 必须由该簇外独立家族支持核心人格。

### `CL-REALITY-CONVERSION`

- 025 只说明资源节点可见与有承接；
- 026、027 描述不同路段，但同一财节点核心计数上限仍为 1；
- 024 若等于 026+027 的同一连续链，只作整链叙事；
- 029、030 只作负向守门；
- 不能把同一财节点拆成现实感、成品力、商业力、责任感和制度化五项优势。

### `CL-CROSS-BRIDGE`

028 连接已有输入端与约束端。桥接不是额外人格证据。若 019 与 011/012 已使用相关事实，028 只替代为更具体叙事，不增加家族数量。

## 5. 组合裁决表

| 组合 | 预期裁决 | 禁止处理 |
|---|---|---|
| 021 + 022 | 同对象取主型；同等级 unresolved | 两条同时算“抗压优势” |
| 023 + 024 | 同对象互斥 | 同时写冲突未解与已通关 |
| 024 + 026 + 027 | 同链时 024 为组合叙事 | 三条算三份核心证据 |
| 025 + 026/027 | 可共存审计，受簇上限 | 资源可见性另算人格优势 |
| 025 + 029 | 同对象正向承接/过载互斥 | 既写稳定承接又写超载 |
| 026/027 + 029 | 路由可存在，但报告释放降级 | 忽略容量风险继续写成优势 |
| 025/026/027 + 030 | 受影响对象正向关闭/降级 | 一边写竞争一边写资源顺畅 |
| 028 + 019 + 011/012 | 028 只作更具体桥接 | 当作第三独立家族 |
| 029 + 016 | 选择更具体负荷来源 | 两条过载重复累计 |
| 030 + 017 | 对同一比劫事实按对象机制择一 | 同时写自主与资源竞争两项特质 |

## 6. 图内事实与图外反例

规则触发只允许使用排盘事实与已冻结工作定义。现实中的：

- 合作协议是否清楚；
- 家庭财务安排；
- 职业是否商业；
- 是否拥有职位；
- 是否成功变现；

只能作为未来可否认行为、反例或情境信息，不得用于研究者临场修正规则。

## 7. 可否认行为最小形式

候选句必须是：

```text
具体情境 + 可观察处理顺序/动作 + 反向条件
```

例如：

- 021：压力出现时是否先形成步骤或样例；若主要反应是回避或持续解释，则不支持。
- 023：正式标准明确时，直接反馈是否常破坏接口；若能稳定补出可交付修改，则不支持未解决状态。
- 026：形成输出后是否推进到可交付对象；若常在表达后停止，则不支持。
- 027：成果出现后是否主动明确责任与后续承诺；若倾向一次性交付，则不支持。
- 028：面对规则是否先整理成内部方法；若只感到压力或直接对抗，则不支持。

这些仍是候选，不得在来源、槽位与第二独立家族关闭前进入真人材料。
