# Batch 02｜状态轴、互斥与证据依赖协议 v0.1

**状态：** F0 Draft / Process Test Only  
**适用规则：** `MC-R-011`—`MC-R-020`  
**合同：** `RULE_DEFINITION_CONTRACT_v1.1-draft.md`

## 1. 目的

Batch 02 的十条规则不能被当作十个彼此独立的人格信号。它们主要是在描述同一组底层事实的不同状态：输入如何到达输出、输出如何外显、输出是否过载，以及自我参照与外部约束如何共同作用。

本协议冻结状态轴、优先级与依赖上限，防止：

- 一条印食链同时被算成“吸收强、表达强、学习强、创作强”四份证据；
- 一组比劫官杀同时被算成“独立、守规则、会协商、抗压”四份证据；
- 同一官杀同现既触发单清，又触发混杂；
- 先写好人格文案，再回头挑能支持文案的规则。

## 2. 输入—输出三轴模型

### Axis IO-R｜路由关系

| 状态 | 触发候选 | 说明 | 可否独立生成核心证据 |
|---|---|---|---|
| `IO-R0 unknown` | 无 | 路由未完成审查 | 否 |
| `IO-R1 input_biased` | MC-R-011 | 有效输入存在，完整检查后输出弱 | 否；只修饰 |
| `IO-R2 integrated` | MC-R-012 | 输入经承接连续到达输出 | 来源门关闭后可作锚点候选 |
| `IO-R3 filtered` | MC-R-013 | 关键输出被有效内部过滤 | 否；只作反向候选 |
| `IO-R4 unresolved` | 冲突未解 | 多条状态同等级成立或必要条件缺失 | 否 |

优先级：

```text
confirmed_filtered (013)
  > general_input_biased (011)
  > unknown
```

`012 integrated` 与 `013 filtered` 对同一关键输出互斥；`011 input_biased` 与 `012 integrated` 对“输出弱/有效”互斥。

### Axis IO-V｜输出显隐

| 状态 | 触发候选 | 说明 | 报告边界 |
|---|---|---|---|
| `IO-V0 unknown` | 无 | 无法确认通道 | 不写 |
| `IO-V1 public_supported` | MC-R-014 | 有根、可达、公开可见 | 来源门关闭后可作锚点候选 |
| `IO-V2 latent_conditional` | MC-R-015 | 只在藏干层，未形成公开通道 | 仅修饰；无情境证据不写行为 |
| `IO-V3 visible_unsustained` | MC-R-009 | 可见但无根/承接 | 只写可见意向，不写能力 |
| `IO-V4 hidden_untriggered` | MC-R-010 | 潜在存在但无引动 | 默认不进入报告 |

优先级：

```text
014 public_supported 与 015 latent_conditional 互斥
009 visible_unsustained 关闭“稳定公开输出”
010 hidden_untriggered 关闭 015 的用户声明释放
```

### Axis IO-L｜输出负荷

| 状态 | 触发候选 | 说明 | 作用 |
|---|---|---|---|
| `IO-L0 unknown` | 无 | 容量/负荷未比较 | 不写 |
| `IO-L1 sustainable_candidate` | 后续链路审查 | 输出有恢复与收口 | 只作守门结果 |
| `IO-L2 overload_candidate` | MC-R-016 | 输出持续高于恢复候选 | 定义未闭合；只作负向守门 |

负荷轴不增加表达正向证据。即使 `014 + 016` 同时满足，也只能保留一份输出通道证据，外加一项节律风险。

## 3. 参照—约束双轴模型

### Axis RC-R｜参照与边界

| 状态 | 触发候选 | 说明 | 可否独立生成核心证据 |
|---|---|---|---|
| `RC-R0 unknown` | 无 | 自我/外部路径未完成检查 | 否 |
| `RC-R1 internal_reference_candidate` | MC-R-017 | 自我参照有效、外部约束经完整检查为弱 | 定义未闭合 |
| `RC-R2 negotiated_boundary_candidate` | MC-R-018 | 两端有效且有中介路径 | 来源门关闭后可作锚点候选 |
| `RC-R3 direct_conflict` | 后续规则 | 两端同场景相战无中介 | 否；反向处理 |

017 与 018 互斥。不得把“比劫有根”既当容量证据又当边界第二证据；容量只作为 gate dependency。

### Axis RC-C｜约束处理

| 状态 | 触发候选 | 说明 | 报告边界 |
|---|---|---|---|
| `RC-C0 unknown` | 无 | 约束不稳定或未完成检查 | 不写 |
| `RC-C1 single_integrated` | MC-R-019 | 一类约束主导且有承接 | 只作外部校准修饰 |
| `RC-C2 mixed_unresolved` | MC-R-020 | 两类约束有效、主次未定且无解 | 定义未闭合；反向候选 |
| `RC-C3 mixed_resolved` | MC-R-038 | 多重约束经过合留/制化形成主次 | 待 Batch 04 审查 |

019、020、038 对同一对象互斥。020 在 038 完成审查前不得进入冻结反向槽。

## 4. 依赖簇上限

### `CL-INPUT-OUTPUT`

正向证据最多计 1 份，除非审计表明确证明使用不同、不重叠的 L0 事实。推荐默认处理：

```text
012 integrated + 014 public_supported
= 1 个输入输出簇贡献 + 1 个显隐说明
≠ 2 个独立人格家族
```

013 和 016 均为负向/守门，不增加第二份正向证据。

### `CL-REFERENCE-CONSTRAINT`

正向证据默认最多计 1 份。只有以下条件同时满足，018 与 019 才允许在内部审计中保留两个不同解释对象：

- 018 的自我参照侧有独立有效事实；
- 019 的约束承接路径不只是复述 018 的同一官杀有效性；
- 两者各自有独立反例；
- 核心原型仍有该簇之外的第三方家族支持。

因此 Batch 02 不允许仅凭 `018 + 019` 生成核心人格。

## 5. 规则组合裁决表

| 组合 | 预期裁决 | 禁止处理 |
|---|---|---|
| 011 + 012 | 二选一；输出有效则 012，输出弱则 011 | 同时写“先吸收”与“输入输出顺畅”并计两份 |
| 011 + 013 | 若关键输出过滤成立，013叙事优先 | 把一般输出弱和主动过滤重复累计 |
| 012 + 013 | 同一关键输出互斥 | 既写顺畅转化又写被强过滤 |
| 012 + 014 | 相关簇最多 1 个正向贡献 | 作为两份独立核心证据 |
| 014 + 015 | 对同一功能互斥 | 同时写公开输出与私域隐藏 |
| 014 + 016 | 输出存在 + 过载守门 | 把 016 再算一次表达强 |
| 015 + 010 | 010 更严格，默认不释放行为声明 | 因多处藏干写“私下很会表达” |
| 017 + 018 | 外部约束弱/有效互斥 | 同时写内定标与可谈判边界 |
| 018 + 019 | 允许共存审计，但受依赖簇上限 | 仅凭二者生成核心人格 |

| 020 + 038 | 未解决/已解决互斥 | 研究者按想要的报告临场选一条 |

## 6. 可否认行为的最小形式

Batch 02 未来允许进入报告的行为句必须包含：

```text
具体情境 + 默认处理顺序/可观察动作 + 反向条件
```

候选示例：

- 012：面对复杂材料，在理解后是否通常会形成一个可供他人回应的版本；若只持续收集而不输出，则不支持。
- 014：形成观点后，是否较常转成文字、作品、样例或明确反馈；若长期只在内部加工，则不支持。
- 018：权限清楚时，是否能接受共同标准但仍要求保留明确自主区；若任何外部标准都被视为控制，则不支持。
- 019：面对明确规则时，是否先整理职责、边界和完成条件；若只感到压力却无法转成行动框架，则不支持。

这些句子仍只是待报告映射的候选，不得在来源、槽位与第二独立家族关闭前进入真人材料。
