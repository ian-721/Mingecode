# M1-B 规则定义合同 v1.0-draft

**状态：** F0 Draft / Research Candidate / Process Test Only  
**适用源包：** `M1A-candidate-v0.1`  
**适用规则集：** `MC-R-001`—`MC-R-040`  
**禁止用途：** 真人裁决、用户展示、准确率宣传、业务实现

## 1. 合同目的

本合同只解决一件事：让两名独立审查者在看到同一组抽象结构事实时，能够判断一条候选规则是否触发、为何关闭、属于哪个证据家族，以及它最多可以生成何种报告声明。

它不证明传统术数关系具有现代人格效度，也不把内部工作定义升级为传统共识。

## 2. 四层对象必须分离

| 层 | 对象 | 允许内容 | 禁止跳跃 |
|---|---|---|---|
| L0 输入事实 | 月令、天干、地支、藏干、根、关系、时间稳定性 | 可复核的结构事实 | 直接写成人格结论 |
| L1 传统结构解释 | 旺衰、显隐、制化、链路、合冲等 | 明确来源层级与争议 | 冒充现代行为证据 |
| L2 项目机制假设 | 容量、外显、恢复、转化、压力处理 | 可反驳、带条件的内部假设 | 冒充心理量表或因果事实 |
| L3 报告声明 | 现代、具体、可否认的行为句 | 只能引用已审查 Rule ID | 自由发挥、漂亮话补洞 |

## 3. 规则必填字段

```text
rule_id
source_package
input_features
necessary_conditions
exclusion_conditions
enhancers
reducers
counterevidence
evidence_family
family_cap_key
mutual_exclusion_group
supersession_rule
dimension_effect

modern_mechanism_hypothesis
falsifiable_behavior
forbidden_inference
technical_disposition

```

缺少必要条件、排除条件、证据家族或反例的规则，不得进入 24 槽试验集。

## 4. 状态词

每条规则的 `review_status` 只能取：

```text
eligible_core
eligible_modifier
sensitivity_only
pending_source
pending_definition
excluded_m1b
```

解释：

- `eligible_core`：只表示具备进入核心试验槽的材料条件；仍未真人验证；
- `eligible_modifier`：只可修饰显隐、场景、稳定性、代价或声明强度，不能独立生成核心原型；
- `sensitivity_only`：只处理时间、边界、争议力量判据或附录；
- `pending_source`：结构定义已接近可用，但正式版本、原文/评注分栏或页码门未关闭；
- `pending_definition`：触发、排除、力量、链路或互斥条件仍无法一致执行；
- `excluded_m1b`：保留历史记录，但不进入当前材料系统。

`eligible_*` 不是“已验证”。所有传统来源正式版本与页码在 F1 Content Lock 前仍需关闭。

## 5. 第一批工作定义

### 5.1 月令稳定

同时满足：

- 使用 `civil_time_v1`；
- 出生地点、时区和节气数据版本明确；
- 距采用的节气边界超过 120 分钟；
- 所有合理候选时间下月令不变化。

不满足时，任何依赖月令的规则只能 `sensitivity_only`，不能在主材料中触发。

### 5.2 根气候选与有效根

`root_candidate` 只表示日主同类在某地支藏干中存在；不得仅凭存在就计为有效根。

F0 下的 `effective_root` 至少要求：

- 所在地支在当前候选盘中稳定；
- 不是只靠一个尚未定义清楚的合化结果成立；
- 未被一条已确认的强关系完整关闭；
- 对应功能不是仅名义残余；
- 审查表记录其位置、依赖与可能关闭它的关系。

根气强弱的完整比较尚未冻结。需要比较“谁更强”的规则不得因此自动进入核心。

### 5.3 独立根

两个根只有在以下情况下才可视为两个恢复入口：

- 位于不同地支；
- 不会被同一个单点时间变化同时消失；
- 不会被同一条已确认关系同时关闭；
- 不是把同一月令信号及其透、藏重复拆成多份证据。

“独立根数量”只进入 `EF-CAPACITY-BASE` 一个家族，不能作为多个独立家族累计。

### 5.4 透干与外显

`visible_stem` 只表示某功能在天干层可见。只有在有根或有效后续承接时，才允许写“较稳定外显”；否则最多写“可见意向或短时出现”。

透干不得直接推出：外向、口才、领导力、才华、职业或社会地位。

### 5.5 藏而不透与无引

`hidden_without_trigger` 至少要求：

- 对应功能只在藏干层出现；
- 天干无对应外显；
- 没有已经通过定义审查的合会、透出或连续功能链将其引出；
- 月令主气没有以其他方式承担同一明显功能。

它只能限制报告：潜在存在不等于稳定行为。不得写“隐藏天赋”“你其实什么都会”。

### 5.6 连续链

一条链只有在每个节点都有效、方向连续、没有中间节点被关闭，且结果实际到达目标功能时才成立。

同一节点被多种术语重复描述时仍只计一次。仅仅“元素齐全”不等于链成立。

### 5.7 容量、负荷与恢复

- `capacity` 是结构承载候选，不是人格强弱或能力等级；
- `load` 是同时需要处理的输出、资源或约束候选，不是坏运；
- `recovery_path` 是有效支持能够到达日主的路径，不是依赖他人；
- 容量与负荷必须分开记录，不能用一个“旺/弱”标签替代。

### 5.8 关系力量

冲、合、刑、害、合化的完整力量比较尚未冻结。涉及“强弱悬殊”“完全合解”“制尽”“冲拔”等裁决时，必须记录：月令、根、透出、通道、救应和时间稳定性。

在统一比较合同完成前：

- `MC-R-003` 只进入敏感性层；
- 合、冲、刑、害、从格不得单独生成核心原型；
- 任何事件、疾病、灾祸、婚姻和贵贱推断均禁止。

## 6. 证据家族与上限

第一批冻结以下家族：

| Family ID | 含义 | 典型 Rule ID | 聚合上限 |
|---|---|---|---|
| `EF-CAPACITY-BASE` | 月令支持、根分布与基础恢复入口 | 001、002、006 | 同一对象只计 1 个家族贡献 |
| `EF-CAPACITY-VULNERABILITY` | 单点支撑及其边界脆弱性 | 003 | 只作负向守门，不增加正向证据 |
| `EF-MONTH-VISIBILITY` | 月令主题透出或内藏 | 004、005 | 同一功能二选一，最多 1 个修饰 |
| `EF-FLOW-CLOSURE` | 容量与出口/转化/约束之间是否闭塞 | 007 | 定义完成前不得计入 |
| `EF-SUPPORT-RECOVERY` | 支持链是否实际到达并帮助恢复 | 008 | 定义完成前不得计入 |
| `EF-VISIBILITY-SUSTAINABILITY` | 可见但无承接，或潜在但无引动 | 009、010 | 每个功能最多 1 个守门声明 |

同一家族的多条规则可用于解释细节，但不能被当作多个独立家族支持核心原型。

## 7. 互斥、继承与覆盖

- `MC-R-001` 与 `MC-R-002` 对同一月令条件互斥；
- `MC-R-002` 是 `MC-R-006` 在“失令”条件下的恢复型子类；两者同时满足时只保留一个家族贡献，报告优先使用 002 的更具体描述；
- `MC-R-004` 与 `MC-R-005` 对同一功能互斥；
- `MC-R-009` 与任何“有根透出”规则对同一功能互斥；
- `MC-R-010` 与任何已经确认引动/连续链的规则对同一功能互斥；
- 互斥只关闭当前对象，不删除历史规则。

## 8. 核心原型门

单一核心候选仍必须同时满足：

- 至少两个独立证据家族同向；
- 至少一个核心锚点或两个支持规则；
- 没有同场景、同等级的未解决反向证据；
- 所有合理时间候选中核心机制稳定；
- 报告行为可被明确否认；
- 不依赖职业、性别、婚姻、财富或社会等级。

本合同第一批没有将 `MC-R-001`—`MC-R-010` 中任何规则升级为 `eligible_core`。

## 9. 版本规则

- 改说明但不改触发语义：patch；
- 改家族、互斥、必要或排除条件：minor；
- 改规则本体层级或核心裁决协议：major；
- F1 后的任何 minor/major 变化必须重新生成夹具、报告映射与冻结哈希。
