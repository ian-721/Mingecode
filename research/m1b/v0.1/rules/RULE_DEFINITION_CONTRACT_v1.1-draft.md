## 1. 版本关系

v1.1 完整继承 v1.0 的四层分离、状态词、根气、显隐、连续链、容量/负荷、关系力量、核心原型门与版本治理。若本文件与 v1.0 对 Batch 02 对象的处理存在差异，以 v1.1 为准；Batch 01 的历史裁决不被回写。

本批新增的目标是把“印、食伤、比劫、官杀”从十神标签拆成三个独立问题：

1. 输入如何进入、是否能经过内部处理到达输出；
2. 输出是否存在、如何外显、是否超过恢复容量；
3. 自我参照与外部约束是缺位、协商、单一整合还是多重冲突。

任何十神名称都不得直接等同学习力、口才、独立、服从、责任感、道德、职位或领导力。

## 2. 新增必填字段

Batch 02 规则除 v1.0 字段外，必须补充：

```text
state_axis
dependency_cluster
gate_dependencies
correlated_rule_ids
specificity_precedence
report_release_level
```

解释：

- `state_axis`：规则描述的是路由、显隐、负荷、参照中心还是约束处理；
- `dependency_cluster`：共享同一批底层事实的相关规则集；
- `gate_dependencies`：必须先通过但不额外计为人格证据的守门条件；
- `correlated_rule_ids`：不得当作独立证据重复累计的规则；
- `specificity_precedence`：多条同时满足时由哪条更具体规则接管叙事；
- `report_release_level`：none / audit_only / modifier_claim / anchor_claim_candidate。

## 3. 输入—输出工作定义

### 3.1 有效输入通道

`effective_input_route` 至少要求：

- 印类结构不是仅名义出现；
- 至少一条支持路径能够到达日主；
- 路径中节点没有被已确认规则完整关闭；
- 所依赖月令、地支和时间在主样本中稳定；
- 审查表记录财制、输出链和其他反向条件。

它只表示“存在可用的吸收/支持候选路径”，不证明学历、智力、记忆、敏感或学习能力。

### 3.2 有效输出通道

`effective_output_route` 至少要求：

- 食神或伤官对应功能有有效根、连续生出路径或其他已审查承接；
- 不属于 `MC-R-009` 的透而无根；
- 未被有效过滤规则完全关闭；
- 若只在藏干层存在，必须区分“潜在存在”与“可稳定出现”；
- 所依赖事实在合理时间候选中稳定。

它只表示“输出候选可到达外部对象”，不证明外向、口才、创意、写作、表演或社交能力。

### 3.3 输出弱

`output_weak` 不能仅由“天干无食伤”判定。必须逐项检查：

- 无有根透出的有效输出；
- 无印身食、身食或其他连续输出链；
- 无合会、引动或多点藏根形成的已审查输出路径；
- 没有一条虽少但足以完成输出的替代路径。

只要任一有效输出路径存在，`MC-R-011` 的“输出弱”条件即不成立。

### 3.4 关键输出通道

`key_output_channel` 要求：

- 该通道承担当前结构中主要可达输出；
- 没有另一条同等级、独立且未被关闭的替代通道；
- 若移除该通道，输出状态会从“有效”变为“弱/不确定”；
- 该判断不能只依据十神数量。

在替代输出检查未完成前，`MC-R-013` 保持 `pending_definition`。

### 3.5 直接过滤

`direct_filtering` 只有在以下条件同时成立时才成立：

- 过滤端与被过滤端均有效；
- 位置、链路和力量足以发生直接作用；
- 不是两个符号的名义同现；
- 被过滤端确为关键输出；
- 没有财制印、替代输出或必要扶身等明确排除条件。

“偏印出现 + 食神出现”不等于 `MC-R-013` 触发。

## 4. 输出负荷工作定义

### 4.1 输出负荷候选

`output_load_candidate` 至少要求一条有效输出通道持续占用容量，而不是一次性或名义输出。

### 4.2 输出超过承载

`output_load_exceeds_capacity` 必须同时满足：

- 输出通道有效且持续；
- 基础容量与恢复路径不足以承接该输出；
- 没有有效财链完成收口；
- 没有比印补充形成恢复；
- 不属于尚未审查完成的特殊从象结构；
- 结论在合理时间候选中稳定。

当前“持续”“不足”和两端力量比较仍缺统一阈值，因此 `MC-R-016` 只能保持 `pending_definition`，可进入负荷守门 dry run，不能生成 D6 锚点。

### 4.3 与输出存在的关系

`MC-R-014` 与 `MC-R-016` 可以同时满足：前者表示输出通道存在，后者表示该输出对恢复构成过载候选。两者不得被相加为两份“表达强”证据；016 只作负向/节律守门。

## 5. 自我参照与外部约束工作定义

### 5.1 有效自我参照候选

`effective_self_reference` 至少要求：

- 比劫相关事实有效且不是单纯数量堆积；
- 日主有基本承载；
- 该信号未被资源竞争规则完整改写；
- 不把容量根气重复计算为第二份边界证据。

它只表示内部/同类参照候选，不证明独立、强势、好胜或不合群。

### 5.2 有效外部约束

`effective_constraint` 至少要求：

- 官或杀不是虚浮标签；
- 有根、来源或连续作用路径；
- 能实际进入责任、标准或压力处理链；
- 未被完全关闭或只在不稳定时间候选中成立；
- 不以职位、道德、权威身份作为证明。

### 5.3 外部约束弱

`constraint_weak` 必须完成官、杀两端及其印化、食制、合留和隐藏路径检查。仅“官杀不透”不足以触发 `MC-R-017`。

在该全局缺失验证器完成前，`MC-R-017` 保持 `pending_definition`。

### 5.4 可谈判边界

`negotiated_boundary_candidate` 至少要求：

- 自我参照与外部约束两端均有效；
- 任一方都未被完全制尽；
- 至少一条印通官身、食伤调节或其他已审查中介路径存在；
- 不属于官杀混杂失序；
- 不存在同场景、同等级的直接相战未解决状态。

这只是“权限与标准可被协商”的项目假设，不得写成成熟、会合作或高情商。

## 6. 官杀单清与混杂工作定义

### 6.1 单清约束

`single_clear_constraint` 至少要求：

- 官或杀一类形成主导；
- 主导端有效且有承接；
- 另一端不存在、虚浮或明确从属；
- 约束能够通过印、食制或容量转成结构/行动；
- 不存在过重无制或多重规范失序。

`MC-R-019` 只允许生成“外部标准可被转成运行框架”的修饰声明，不得生成职位、道德、服从、领导或成功推断。

### 6.2 官杀混杂且无解

`mixed_constraint_unresolved` 必须同时满足：

- 官与杀分别有效，且不是同一事实的重复标签；
- 两端都对当前结构发生作用；
- 没有明确主次；
- 没有已验证的合留、食制、印化、从一方或其他解决路径；
- 结论不依赖岁运；
- 合理时间候选中状态稳定。

在 `MC-R-038` 的解决机制完成后续审查前，`MC-R-020` 保持 `pending_definition`。官杀同现本身不等于混杂。

## 8. 相关依赖簇与去重

### `CL-INPUT-OUTPUT`

包含 `EF-INPUT-OUTPUT-ROUTING`、`EF-OUTPUT-CHANNEL`、`EF-OUTPUT-LOAD`。

- 012 与 014 若共享同一条食伤链，不能自动算作两个独立家族；
- 只有审计表证明二者使用不重叠的 L0 事实，才可分别保留；
- 016 无论如何只作负向守门，不增加第二份正向证据；
- 核心原型仍须从该簇之外获得至少一个独立家族。

### `CL-REFERENCE-CONSTRAINT`

包含 `EF-REFERENCE-BOUNDARY` 与 `EF-CONSTRAINT-PROCESSING`。

- 018 与 019 若复用同一官杀事实，不自动算作两个独立家族；
- 018 的比劫/自我参照侧必须有独立事实，且 019 的约束承接侧另有有效路径，才允许分别保留；
- 核心原型仍须至少有一个该簇之外的独立家族，防止只凭比劫官杀组合定义整个人格。

## 9. 互斥、覆盖与共存

- 011 与 012 对同一对象的“输出弱 / 输出有效”状态互斥；
- 013 若满足关键输出被直接过滤，优先于 011 的一般“输出弱”叙事，并关闭 012；
- 012 与 013 对同一关键输出互斥；
- 014 与 015 对同一功能的公开有效 / 藏而不透状态互斥；
- 015 若同时命中 010，采用 010 的更严格“不进入报告”守门；
- 014 与 016可共存，但只保留一份输出正向证据，016只修饰节律与代价；
- 017 与 018 对外部约束弱 / 双向有效状态互斥；
- 019 与 020 对单清可整合 / 多重未解决状态互斥；
- 020 与后续 038 互斥；038 未审查前，020不得释放为反向槽。
