# CRX-0.5｜跨批次互斥、覆盖与依赖簇回归

**版本：** `CRX-0.5.0-draft`  
**覆盖范围：** `MC-R-001`—`MC-R-040`  
**状态：** Process Test Only / Not Human-Tested  
**真人测试：** NOT AUTHORIZED

## 1. 回归目的

四批逐条审查完成后，不能把每条规则继续当作彼此独立的“人格加分项”。本回归统一检查：

- 同一对象上的互斥状态；
- 更具体机制对一般标签的覆盖；
- 同一证据家族、依赖簇和端点的重复计数；
- 时间边界、容量、负荷和竞争守门；
- 综合门、桥接链和关系状态是否被误当成新证据；
- 报告释放是否满足至少两个独立家族。

本回归不证明任何现代人格机制有效，只判断内部材料是否自洽、可反驳和不可随意选规则。

## 2. 全局裁决顺序

任何候选报告生成前，按以下顺序执行，不得跳步：

1. **时间资格门**：`civil_time_v1`、时辰/节气/DST/历史时区与候选盘稳定性；
2. **对象有效性**：节点、根、连续链、直接作用、来源和去向；
3. **硬排除**：035、036、040不得进入核心或用户声明；
4. **具体机制优先**：对象特定链路、冲突、过滤、竞争优先于一般关系标签；
5. **互斥状态裁决**：同一对象只能保留一个主状态；
6. **家族/簇/端点上限**：相关事实最多贡献一份正向证据；
7. **负荷与冲突守门**：只限制或降级，不增加人格正向证据；
8. **综合门检查**：007/039、028、037等不得成为独立家族；
9. **核心门**：至少两个彼此独立的证据簇同向；
10. **报告释放门**：规则状态、来源、反例和具体行为全部可追溯。

## 5. 核心候选释放规则

一份核心候选必须同时满足：

- 至少两个不同 dependency cluster 提供同向、非重复事实；
- 其中至少一个是对象特定的可执行机制，不是显隐、关系标签或综合门；
- 没有同场景同等级未解决反向状态；
- 时间候选不改变核心机制；
- 负荷、竞争和过滤没有关闭主链；
- 每个用户声明均有可否认行为和反向条件；
- 来源门与现代机制验证仍分别标记，不得互相替代。
