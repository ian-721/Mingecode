**继承对象 Blob SHA：** `354c00823e3cb81a5fbf8b50650e947fbff77210`

**禁止用途：** 真人裁决、用户展示、准确率宣传、业务实现

## 1. 版本关系

v1.2 完整继承 v1.0—v1.1 的四层分离、根气、显隐、连续链、容量/负荷、状态轴、证据家族、依赖簇、互斥和核心门。Batch 01—02 的历史裁决不回写；本文件只新增 Batch 03 的压力接口、现实转化、桥接、资源负荷与资源竞争合同。

本批禁止把传统结构标签直接等同：

- 制杀 = 掌权、英雄、强者；
- 伤官 = 叛逆、天才、创新；
- 财 = 财富、商业能力、配偶；
- 官 = 职位、道德、领导力；
- 印 = 学历、聪明、体制适配；
- 比劫争财 = 败家、破财、克妻、兄弟不和。

## 2. Batch 03 新增必填字段

```text
target_object_id
pressure_or_standard_type
route_nodes
route_edges
bridge_node
bridge_closes_conflict
resource_object_scope
resource_source_status
resource_destination_status
capacity_dependency_ids
competition_object_scope
competition_is_direct
competition_protection_routes
subtype_precedence
cross_cluster_dependencies
report_release_level
```

- `target_object_id`：压力、标准、输出或资源必须指向可审计对象，不能只写“全局有某十神”。
- `route_nodes/edges`：链路必须列出节点及相邻作用，不接受标签并见即成链。
- `bridge_node`：通关节点必须实际承接前一端并到达后一端。
- `resource_object_scope`：同一财节点、不同财节点或不同情境必须分开。
- `capacity_dependency_ids`：容量只作门，不自动增加人格证据。
- `competition_object_scope`：争夺必须发生在同一关键资源对象上。
- `report_release_level`：`none | audit_only | modifier_claim | anchor_claim_candidate`。

## 3. 压力处理工作定义

### 3.1 有效压力节点

`effective_pressure_node` 至少要求：

- 七杀不是虚浮标签；
- 有根、来源或连续作用路径；
- 能实际到达当前结构，而不是只在无关位置名义存在；
- 未被另一已审查机制完全关闭；
- 在合理时间候选中稳定。

它只表示“存在需要处理的强制/压力候选”，不证明危险、权力、胆量、武职或领导力。

### 3.2 关键压力响应通道

`key_pressure_response_channel` 要求：

- 食神或伤官通道有效；
- 该通道直接作用于同一压力对象；
- 没有同等级、独立且未处理的替代通道；
- 移除该通道会使压力状态由“可处理候选”变为“未处理/不确定”；
- 日主容量能够同时承接压力端与输出端。

### 3.3 食神制杀候选

`methodical_pressure_response_candidate` 仅在以下条件同时成立时触发：

- `effective_pressure_node = yes`；
- 食神为关键、有承接的输出；
- 食神到压力节点的直接制约成立；
- 偏印未完整关闭食神；
- 财未使输出改向继续生杀；
- 官杀混杂未解不成立；
- 容量与时间稳定。

它最多支持“压力来临时倾向先形成可执行处理步骤”的项目假设，不证明掌权、临危天赋或情绪成熟。

### 3.4 伤官制杀候选

`reframing_pressure_response_candidate` 与 3.3 使用相同硬门，但关键输出为伤官。它最多支持“面对僵硬压力时倾向提出质疑、重定义或公开反馈”的项目假设，不自动增加 D1，不证明叛逆或反权威人格。

### 3.5 子类型裁决

对同一压力对象：

```text
021 methodical
022 reframing
```

默认互斥。若两条通道均有效且一方有清楚主导，则只释放主导子类型；若同等级且无法预注册主导，状态为 `mixed_or_unresolved`，不得为了报告好看临场选择。

## 4. 表达—正式标准接口

### 4.1 直接接口冲突

`expression_standard_conflict_unresolved` 必须同时满足：

- 伤官输出有效；
- 正官标准有效；
- 二者作用于同一对象、同一情境并直接接触；
- 无有效财桥；
- 无有效印制伤护官；
- 不属于伤官伤尽；
- 不属于官虚；
- 结论在合理时间候选中稳定。

它只描述“表达/反馈与正式标准的接口未解决”，不得写成灾祸、官非、反骨或必然破坏合作。

### 4.2 财桥已解决

`expression_standard_bridge_resolved` 要求完整连续链：

```text
effective_output(伤官)
  -> effective_resource_bridge(财)
  -> effective_formal_constraint(官)
```

财必须实际承接输出并到达正式标准；只见伤官、财、官三个标签不成立。命中后关闭 MC-R-023，但 MC-R-024 只作为**组合修饰**，不得把同一链拆成 024、026、027 三份独立证据。

### 4.3 不同情境

若表达冲突与财桥分别发生于不同对象或不同情境，允许记录情境分化，不得用“有通关”覆盖全部冲突，也不得把局部冲突升级成全局人格。

## 5. 现实转化工作定义

### 5.1 有效资源/完成节点

`effective_resource_node` 至少要求：

- 财节点有根、来源或可达路径，不是虚浮标签；
- 节点对应的对象范围明确；
- 来源或去向至少一端有效；
- 未被同对象的竞争、过载或断链完整关闭；
- 容量与时间稳定。

“资源/完成节点”是项目内部结构语言，不等于钱、商业、市场、配偶或社会现实能力。

### 5.2 可持续公开资源通道

MC-R-025 只记录：

```text
resource_channel = public_and_supported
```

它可作为 D5 的显隐/承接修饰，不独立生成“会赚钱、会经营、现实能力强、擅长收口”等人格结论。

### 5.3 输出到资源/完成

`output_to_resource_route` 要求：

- 有效输出有持续来源；
- 财节点能承接；
- 输出到财的边连续；
- 输出未被关键过滤关闭；
- 同对象无已确认资源竞争；
- 容量不过载。

MC-R-026 在来源门关闭后可作为 D5 锚点候选；若与 012/014 使用同一输出端，与 025 使用同一财端，必须按依赖簇去重。

### 5.4 资源到正式承诺

`resource_to_constraint_route` 要求：

- 财节点有明确来源；
- 财到官的边连续；
- 官有效且不过重；
- 有日主或印承接责任；
- 官杀混杂未解不成立；
- 表达—标准直接冲突未解不成立。

MC-R-027 在来源门关闭后可作为 D5/D1 接口候选，但不得推出职位、仕途、社会地位或领导力。

### 5.5 官印内化桥

`constraint_to_internal_support_route` 要求：

```text
effective_constraint
  -> effective_input/support(印)
  -> 日主
```

链须连续，且无财完整破印、混杂未解或官杀过重无制。MC-R-028 只作桥接修饰；它复用 Batch 02 的约束端和输入端，不能成为第三个独立证据家族，不证明学历、道德、贵气或体制适配。

## 6. 资源负荷工作定义

### 6.1 资源负荷候选

`resource_load_candidate` 不是“财多”数量判断，而是多个有效、持续、同一时段占用容量的资源/责任对象。

### 6.2 负荷超过容量

MC-R-029 必须同时满足：

- 至少两个有效负荷对象或一个持续高占用对象；
- 基础容量与恢复路径不足；
- 比印补充不足；
- 有效分流、收口或退出路径不足；
- 不属于严格从财候选；
- 结论在时间候选中稳定。

当前“持续、高占用、恢复不足”仍缺统一分类阈值，严格从财排除也未完成，因此 MC-R-029 保持 `pending_definition`，只可作为负向守门 dry run。

### 6.3 与 MC-R-016 去重

若 016 与 029 共享同一容量/恢复事实，只允许一条具体过载叙事：

- 输出占用为主：016；
- 资源/责任对象占用为主：029；
- 无法区分：`load_source_unresolved`。

二者均不得增加正向人格证据。

## 7. 资源竞争工作定义

### 7.1 直接资源竞争

MC-R-030 只有在以下条件全部成立时才继续：

- 比劫有效；
- 关键财节点有效；
- 二者在同一对象范围内发生直接竞争；
- 财缺少图内官护、持续食伤来源或其他有效保护；
- 比劫不是日主必要支持；
- 竞争状态在时间候选中稳定。

### 7.2 图外现实信息不得作为排盘触发器

M1-A 原规则中的“合作分配机制清楚”不是盘面可观察事实。v1.2 将其移出 deterministic trigger，改为：

- 未来行为反例/情境变量；
- 报告可否认问题；
- 不得用于研究者临场关闭或开启规则。

### 7.3 与 MC-R-017 的优先级

同一比劫事实不得同时支持：

```text
017 internal_reference_candidate
030 resource_competition_candidate
```

若资源对象、直接作用和竞争条件完整，030 的对象特定叙事优先；若比劫是必要扶身或参与资源生成，则 030 关闭，不能用“争财”改写主体边界。

### 7.4 对正向资源链的影响

对同一财对象，030 成立时关闭或降级 025、026、027 的正向报告释放。不同对象必须分别审计，不得从一处竞争推断“整体资源关系都竞争”。

## 9. Batch 03 依赖簇

### `CL-PRESSURE-INTERFACE`

包含 021—024，并复用 Batch 02 的输出端和约束端。

- 同一压力/标准对象最多一个正向簇贡献；
- 021/022 为压力处理子型；
- 023/024 为未解决/已解决接口；
- 024 不得因连接三个节点而被算成三份证据；
- 核心原型仍须有簇外独立家族。

### `CL-REALITY-CONVERSION`

包含 024—027、029、030，并围绕同一资源节点。

- 同一资源对象最多一个正向贡献；
- 025 只作显隐/承接说明；
- 026/027 若连续构成长链，可保留不同路由说明，但核心计数仍受簇上限；
- 029/030 为负向守门，不增加正向证据；
- 不得把同一财节点同时包装成“现实、产出、制度、商业、资源敏感”多项优势。

### `CL-CROSS-BRIDGE`

MC-R-028 连接 Batch 02 的 `CL-REFERENCE-CONSTRAINT` 与 `CL-INPUT-OUTPUT`。

它只说明桥接状态，不得因为连接两个已计端点而成为第三个独立家族。若 019 与 011/012 已使用相关官印事实，028 只能作更具体叙事修饰。

## 10. 互斥、覆盖与共存

- 021 与 022：同一压力对象默认一主型；同等级则 unresolved。
- 023 与 024：同一接口的未解决/已解决互斥。
- 024 与 026+027：同一链时 024 为组合叙事，不新增证据。
- 025 与 029：同一资源对象的可持续承接/容量超载互斥。
- 025 可与 026/027 共存审计，但受现实转化簇上限。
- 026/027 可在结构上存在而 029 同时提示过载；此时正向报告释放必须降级或关闭。
- 030 对同一资源对象成立时关闭或降级 025/026/027。
- 028 与 019、011/012 共享端点时只作桥接修饰。
- 030 与 017 对同一比劫事实执行对象特定优先级，不重复计数。
- 029 与 016 共享容量事实时只保留更具体负荷来源。
