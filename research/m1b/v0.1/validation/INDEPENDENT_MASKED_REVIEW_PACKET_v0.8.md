# CRX-0.8｜独立遮名内容评审包

**用途：** F1 前的材料评审，不是正式真人盲测  
**版本：** `IMR-0.8.0`  
**报告来源：** `REPORT_MASTER_REBUILD_v0.7.md`  
**禁止：** 向评审者展示原型名、Rule ID、机制名、映射表或项目偏好

## 1. 评审者资格

评审者必须：

- 未参与四份正文的起草或规则裁决；
- 评审前未阅读本仓库的报告标题、Rule ID 或映射文件；
- 不根据认识赵焱阳、延雨婷或其他项目成员来猜测文本；
- 只判断材料本身的区分、体面度、声望与可否认性；
- 不提交本人出生资料，也不把评审当作“哪份像我”的人格测试。

最低要求为 1 名独立评审者；2 名更稳妥。任何项目作者自审不得计入独立评审数量。

## 2. 分配顺序

- Form X：`B → C → D → A`
- Form Y：`A → C → B → D`

同一评审者只使用一个顺序。若有两名评审者，应分别使用 X 与 Y。

# 文本 A

## 运行方式

面对已经形成的内容，你通常会寻找明确的完成对象：交付给谁、什么算完成、结果之后是否还有后续责任。

## 高光状态

当输出进入具体完成接口时，你能把版本推进成可使用成果，并说明谁承接下一步、哪些标准需要持续遵守。

## 翻车方式

若已有可见版本，却缺少接收对象或完成标准，你可能停在“有东西可看”而不是“本轮已完成”，继续寻找明确接口。若成果已完成但责任主次不清，后续承诺也不会自动成立。

## 常见误解

别人可能把你对完成边界的追问理解成只看结果；更准确的是，你需要知道成果如何被接收，以及责任在哪里结束。

## 任务与决策场景

目标、接收方和完成标准明确时，这一机制更容易出现；纯探索、尚不需要交付的阶段，不适合过早收口。若你满足于一次输出而不关心接收和后续责任，这份描述不支持你。

## 关系与使用建议

把“本轮完成”与“后续承诺”分开记录，先定义当前交付，再决定是否继续承担；不要用模糊的长期责任替代清楚的本轮边界。

# 文本 B

## 运行方式

进入合作前，你通常需要知道哪些事项由自己决定、哪些遵循共同标准、哪些责任必须由特定角色承担。

## 高光状态

当权限、标准和中介路径清楚时，你可以保留自己的判断，同时接受共同约束，不必在完全服从和完全拒绝之间二选一。

## 翻车方式

多套标准同时有效却没有主次时，你可能把同一问题按不同口径来回处理，难以稳定选择主标准；若主次已经形成，这种状态应当关闭。

## 常见误解

别人可能把你的确认理解成难合作；更准确的是，你需要责任范围、修改权限和退出方式足够明确。接受共同目标，并不等于所有决定都来自同一角色。

## 任务与决策场景

职责稳定、标准可说明时，你更容易进入协作；角色不断变化、多人都能临时改口径时，你更可能要求重谈边界。若你在权责模糊的合作里也很少需要澄清，这份描述不支持你。

## 关系与使用建议

同时写出不可协商项、可协商区和重新评估条件，并标明谁提出建议、谁授权修改、谁承担最终责任。

# 文本 C

## 运行方式

当一个判断基本成形后，你通常倾向把它变成文字、样例、作品或明确反馈，让内容进入可观察、可回应的状态。

## 高光状态

需要把抽象讨论变成具体对象时，你会先提出一个可指认版本，使他人能够回应其中的观点、形式或执行条件，而不是继续停留在模糊共识。

## 翻车方式

如果输出只是表面可见却缺少稳定承接，你可能频繁给出首版，却难以持续补全；可见不等于已经形成稳定能力。

## 常见误解

别人可能把主动给版本理解成抢结论；更准确的是，你会先把已经成形的判断放到外部，再继续讨论和修订。

## 任务与决策场景

问题需要说明、展示或获得回应时，这一机制更容易出现；完全私密、无需回应的任务，不一定触发同样的输出倾向。若你通常长期只在内部加工而很少外化，这份描述不支持你。

## 关系与使用建议

发出内容时标明“草案、待确认、最终版”，并先确认对方回应的是观点、形式还是执行条件；稳定承接比频繁曝光更重要。

# 文本 D

## 运行方式

面对信息量大的问题，你通常先确认背景、限制和关键概念，再形成第一版。关键信息不足时，你更可能暂缓结论，而不是用速度替代判断。

## 高光状态

当输入与输出两端都有效时，你能把复杂材料整理成别人可以回应的版本，既保留必要上下文，也不会只停在收集。

## 翻车方式

如果输入持续增加，而关键输出仍弱或被内部过滤，你可能继续补材料，使首版晚于需要回应的节点。

## 常见误解

别人可能把延迟表态理解成没有意见；更准确的是，你需要先确认哪些信息真正参与判断，哪些只是环境噪声。

## 任务与决策场景

材料充足、允许梳理时，你更容易给出结构清楚的版本；要求立即回答又缺关键背景时，这一顺序可能被打断。若你经常在信息很少时也能直接定稿，这份描述不支持你。

## 关系与使用建议

先写下最低输入条件和首版截止点，到点输出可修订版本；把“还缺什么”与“已经能说什么”分开，避免让补充材料无限延长。

# 3. 独立评审表

## A. 中心机制复述

请分别用一句不带赞美或贬低的话说明每份文本主要处理什么：

```text
A：
B：
C：
D：
```

## B. 体面度与声望

每题必须选一个最强项；允许写“无法区分”，但需要说明原因。

```text
哪份最像能力更强：
哪份最像更成熟/更会合作：
哪份最像更负责/更可靠：
哪份最像一项职业技能而非人格机制：
哪份正向描述最有吸引力：
哪份代价最像可以忽略的温柔缺点：
```

## C. 六组成对区分

对每一对写出一个**可观察差异**。若不能区分，直接写“不能区分”：

```text
A vs B：
A vs C：
A vs D：
B vs C：
B vs D：
C vs D：
```

## D. 合并判断

```text
最应该合并的一对：
原因：
最不应该合并的一对：
原因：
```

## E. 可否认性

对每份文本各写一个现实行为，若出现便会明确不支持该文本：

```text
A：
B：
C：
D：
```

## F. 职业替代人格检查

标记任何让你联想到下列职业能力的句子：管理、产品、写作、表达、项目推进、沟通协调、执行、交付、责任感。说明该联想来自机制本身，还是文案包装。

## G. 评审声明

```text
我未查看文本映射、原型名称、Rule ID 或作者偏好：是 / 否
我未把本次任务当作本人性格测试：是 / 否
我是否参与过这些文本起草：是 / 否
评审日期：
评审者匿名编号：
使用表单：X / Y
```

评审完成后只返回本表，不接触映射文件。研究者必须先登记原始回答，再揭盲裁决。
