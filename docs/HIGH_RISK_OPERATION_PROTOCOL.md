# 高风险操作协议

**状态：冻结 / Accepted**

本协议定义 Mingecode 仓库中高风险操作的提示词完整性、分阶段授权、资源绑定、最小权限和中断恢复要求。协议只约束执行方式，不授予任何操作权限，也不放宽 docs-first、M1 准入或其他既有禁令。

## 1. 适用范围

高风险操作至少包括：

- Pull Request Ready 转换；
- Merge；
- 发布或部署；
- 生产环境配置变化；
- 数据库迁移；
- 数据删除或覆盖；
- 文件、分支、tag 或 release 删除；
- force push；
- 历史重写；
- 权限或仓库可见性变化；
- secret 或 token 操作；
- 外部消息、邮件或公开发布；
- 任何不可轻易撤销、可能影响他人或生产数据的动作。

无法确定某项操作是否属于高风险时，必须按高风险操作处理并停止推断授权。

## 2. 提示词完整性协议

所有高风险任务提示词必须包含：

- `PROMPT_ID`；
- `EXPECTED_SECTIONS`；
- `EXECUTION_MODE`；
- 从 1 到 N 连续编号的章节；
- 唯一的末尾终止标记，且该标记必须是提示词物理上的最后一行：

```text
=== END OF PROMPT | <PROMPT_ID> | N/N ===
```

在调用任何工具、执行命令、读取 GitHub 或操作仓库前，代理必须核对章节数、编号、标识和最后一行。全部一致时，只能回显以下收件回执，然后停止并等待明确授权：

```text
PROMPT_RECEIPT
PROMPT_ID: <PROMPT_ID>
RECEIVED_SECTIONS: N/N
LAST_LINE: === END OF PROMPT | <PROMPT_ID> | N/N ===
STATUS: WAITING_FOR_EXPLICIT_AUTHORIZATION
```

收件回执只证明提示词完整，不构成 Ready、Merge、部署、迁移、删除或其他写操作授权。若终止标记、章节数、连续编号、任务正文或操作授权有缺失、不一致或疑似截断，只能输出：

```text
PROMPT_INCOMPLETE: STOPPED
```

出现上述异常时，不得先读取仓库、调用工具或执行命令，也不得根据以下信息补全指令：

- 历史对话；
- 用户长期偏好；
- PR 现状；
- 任务标题；
- 常规工作流；
- 任务上下文；
- “显然的下一步”。

## 3. 两阶段授权协议

提示词完整性校验是进入两阶段授权前的门槛，不属于其中任何一个阶段。顺序固定为：

1. 完整性校验并回显收件回执；
2. 用户明确授权进入任务；
3. 第一阶段只读审计；
4. 用户在新的独立消息中提供精确写操作授权；
5. 第二阶段只执行已授权的最小写操作。

### 第一阶段：只读审计

第一阶段只允许：

- 读取真实状态；
- 核验 SHA；
- 检查评论、review、CI 和阻塞项；
- 报告风险；
- 输出绑定精确资源和 SHA 的拟执行操作。

第一阶段不得：

- Ready；
- Merge；
- 部署；
- 迁移；
- 删除；
- push；
- 修改工作区、索引、当前分支或提交历史；
- 改变任何其他远端状态。

用于刷新远端引用的 fetch 仅属于读取真实状态，不得伴随 push 或其他远端写操作。

### 第二阶段：独立写操作授权

每个高风险任务必须预先定义精确授权令牌。只有用户在第一阶段完成后的新独立消息中完整发送该令牌，并且令牌绑定的资源与实时核验结果全部一致，代理才可执行对应写操作。授权令牌单次使用，执行范围不得扩张。

不得将以下内容解释为高风险写操作授权：

- “继续”；
- “好的”；
- “没问题”；
- 一般性同意；
- 之前某条消息中的授权；
- 推断出的用户意图。

任何字段遗漏、状态漂移或标识不符都会使授权失效。执行写操作前必须再次只读核验。高风险操作不得自动继续或自动恢复。

## 4. 精确资源绑定

高风险授权必须精确绑定：

- Repository；
- PR、workflow、环境、数据库或其他目标资源；
- Base SHA；
- Head SHA；
- 预期当前状态；
- 允许的唯一操作；
- 明确禁止的替代操作。

任一标识、SHA 或状态不符时必须停止，不得尝试修复、换用其他资源或选择替代操作。

Merge 授权还必须明确：

- PR 编号；
- Base SHA；
- Head SHA；
- Merge 方式；
- 是否允许 Ready；
- 是否允许 auto-merge；
- 是否允许删除分支。

## 5. 最小写权限

代理只能执行明确授权的最小动作。各项权限默认相互独立，包括但不限于：

- 获得 Merge 授权不等于获得删除分支授权；
- 获得部署授权不等于获得数据库迁移授权；
- 获得 Ready 授权不等于获得 Merge 授权；
- 获得 commit 授权不等于获得 push 授权；
- 获得 push 授权不等于获得创建或合并 PR 授权。

未明确授予的动作一律视为禁止。

## 6. 中断与恢复

若用户中途停止任务：

- 立即停止所有后续写操作；
- 不得自行继续或恢复；
- 不得自动完成“剩余明显步骤”；
- 必须重新读取真实状态；
- 必须区分已完成、未完成和不确定步骤；
- 不得重复执行可能已经成功但状态尚未确认的写操作；
- 恢复任务必须使用新的 `PROMPT_ID` 和新的授权；
- 恢复过程必须先只读核验，再提出绑定实时状态的写操作请求。

回滚或补救也是独立的高风险操作，不得因任务中断而自动执行。

## 7. 最终报告

最终报告必须明确区分：

- 计划执行；
- 实际执行；
- 未执行；
- 因停止而未完成；
- 本地只读操作；
- 本地写操作；
- 远端写操作；
- 最终资源状态；
- 是否需要补救或回滚；
- 尚未验证的事项。

不得把推测、缓存状态或预期结果写成已验证事实。

## 8. 安全原则

**宁可因信息不完整而停止，也不得根据上下文补全高风险操作。**
