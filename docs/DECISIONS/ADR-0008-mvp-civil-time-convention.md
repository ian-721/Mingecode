# ADR-0008：MVP采用民用标准时间口径

**状态：冻结 / Accepted**

- **Title:** MVP采用民用标准时间口径
- **Status:** Accepted
- **Date:** 2026-07-27

## Context

八字排盘可能涉及民用标准时间、真太阳时、时区、夏令时、子时换日及节气边界等不同口径。若不先冻结基础时间口径，同一输入可能产生不同排盘特征，进而破坏规则可复现性、版本比较、错配报告和盲测有效性。

原始 M0 规划已经决定默认使用 `civil_time_v1`，暂不启用真太阳时。本 ADR 将该历史决定纳入活跃文档基线，但不提前回答仍需研究的历法边界问题。

## Decision

- MVP 默认使用用户出生地对应的民用标准时间口径，版本标识为 `civil_time_v1`。
- MVP 不自动将用户输入转换为真太阳时。
- 真太阳时不作为 MVP 核心排盘输入。
- 所有规则结果、测试夹具和报告必须记录时间口径版本。
- 不得在不同用户或不同报告之间静默混用时间口径。
- 不得因为某个结果“看起来更准”而临时切换时间口径。
- 用户输入时间存在不确定性时，必须标记不确定，而不是伪造精确。
- 时区、夏令时、子时换日、节气边界和出生时间不确定性仍需在 M1 中建立独立边界测试。
- `civil_time_v1` 只冻结 MVP 使用的时间基础，不代表所有历法边界规则已经完成研究。
- 未来若引入真太阳时，必须通过新的 ADR、版本号和回归测试，不得静默替换。

## Consequences

- M1 规则研究必须以统一时间口径生成材料。
- 四选一报告不得混用不同时间口径。
- 后续排盘数据模型必须包含 `time_convention_version`。
- 边界案例需要建立敏感性测试。
- 真太阳时可以保留为未来研究候选，但当前排除在 MVP 默认路径之外。

## Supersedes / Superseded by

- **Supersedes:** 无。
- **Superseded by:** 无。

## Open questions

- 子时换日采用何种明确规则？
- 夏令时和历史时区数据如何处理？
- 出生时间只有模糊区间时如何输出？
- 靠近节气与时辰边界时如何表达稳定性？
- 是否需要为边界用户生成多个候选结果？

以上问题均为**待核验 / Pending Verification**，本 ADR 不回答或冻结这些边界规则。
