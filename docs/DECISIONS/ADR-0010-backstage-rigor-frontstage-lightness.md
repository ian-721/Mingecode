# ADR-0010｜后台严谨、前台轻松与传播优先

**状态：Accepted**  
**日期：2026-07-30**

## 背景

M1-A 与后续规则研究已经形成时间边界、结构签名、冲突守门、来源追踪、反巴纳姆和不确定性治理。这些工作可以提高内部判断的稳定性，但若直接暴露到前台，会把一个轻量小工具变成命理报告、心理测量或研究系统。

命格译码第一版的价值不在于向用户展示推算复杂度，而在于让用户用很短的时间得到一份：

- 看得懂；
- 有具体识别感；
- 有一点幽默；
- 有真实但不讨好的翻车点；
- 适合截图和转发；
- 不需要相信宿命论也能使用的结果。

## 决定

### 1. 后台保留严谨研究

后台允许保留：

- `civil_time_v1` 与时间边界；
- 排盘事实与结构签名；
- 候选排序、关闭条件和不确定性；
- 三题校准路由；
- 命盘候选与现实回答的一致、适应、分情境或未决关系；
- 证据去重、来源登记和内部审计；
- 不向用户展示的离散裁决信息。

后台复杂度不得成为前台信息量扩张的理由。

### 2. 前台固定为轻量体验

MVP 前台只允许形成以下主流程：

```text
出生信息
→ 默认三道、最多四道校准题
→ 结果页
→ 分享卡或分享链接
```

用户不需要理解十神、旺衰、证据家族、结构签名、版本页码或内部裁决。

### 3. 前台不展示精确度表演

前台禁止：

- 百分比、准确率、人格分数和雷达数值；
- 规则编号、古籍页码和内部权重；
- “系统已经完全看透你”式权威表达；
- 以推算复杂度替代内容质量。

准确感应来自具体行为、真实代价、明确不适用条件和命盘/现实之间的关系说明。

### 4. 幽默服务于认领，不服务于冒犯

允许的幽默：

- 具体场景中的轻微自嘲；
- 一眼能认出的生活习惯；
- 温和、可分享的小损句；
- 用户可以笑着说“这个确实有”。

禁止：

- 人身贬低、诊断、羞辱和恐吓；
- 把缺点包装成“太优秀”；
- 依赖短命网络梗；
- 把用户写成天选之子或失败者。

### 5. 用户文案单独版本化

内部工作名、结构说明和研究示例不得自动进入产品。

正式前台文案必须独立经历：

```text
行为事实
→ 口语化改写
→ 幽默与节奏编辑
→ 去AI味审查
→ 产品负责人和视觉体验负责人共同批准
```

任何结构变化不应顺手改写文案；任何文案变化也不应静默改变机制含义。

### 6. 分享卡不暴露敏感信息

分享卡不得出现：

- 出生日期、出生时间、出生城市；
- 四柱、十神或完整命盘；
- 内部分数和候选排序；
- 用户回答明细。

分享内容只承担识别、会心和引导朋友体验的职责。

## 后果

### 正面

- 保留前期硬研究的质量收益；
- 不让研究复杂度污染用户体验；
- 前台可以围绕认领、幽默和传播单独迭代；
- 用户无需理解或接受传统命理术语；
- 结果可以诚实表达不确定性，而不显得像学术报告。

### 代价

- 需要维护后台模型版本和前台文案版本两套资产；
- 用户可能看不到系统为何复杂，需要在“查看依据”中提供极简解释；
- 文案不能依赖批量生成后直接上线，必须有人类编辑与共同裁决。

## 明确不授权

本 ADR 不授权：

- 业务代码；
- 真人测试；
- 完整视觉系统；
- 批量正式结果文案；
- 使用大模型在运行时自由裁决人格。
