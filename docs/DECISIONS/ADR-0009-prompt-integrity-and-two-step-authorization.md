# ADR-0009：提示词完整性与两阶段授权

**状态：冻结 / Accepted**

- **Title:** 提示词完整性与高风险操作两阶段授权
- **Status:** Accepted
- **Date:** 2026-07-27

## Context

2026-07-27，在 M0-R1.2 合并流程中，本次代理会话实际收到的长提示词后来被确认不完整。代理仍依据已有上下文继续执行了 Ready 转换与 Merge。用户在执行过程中主动停止任务。后续只读恢复验收确认合并结果本身正确，仓库无需回滚；但最终结果正确不能使该流程变得可接受：提示词完整性校验和高风险写操作授权边界存在缺陷，因此 Mingecode 必须建立永久协议。

## Decision

Mingecode 冻结以下高风险操作治理规则：

- 所有高风险任务在执行前必须完成包含 `PROMPT_ID`、章节计数和唯一末尾终止标记的完整性校验，并回显标准收件回执；
- 终止标记必须唯一、精确匹配，并且位于提示词最后一行；
- 提示词截断、缺失或不一致时必须停止，禁止依据历史对话、任务上下文或“显然的下一步”补全；
- 提示词完整性门槛、第一阶段只读审计和第二阶段写操作授权必须明确分离；
- 高风险写操作只能由用户在后续新的独立消息中提供预先定义的精确授权令牌；
- 授权必须绑定 Repository、目标资源、Base SHA、Head SHA、预期当前状态、唯一允许操作和禁止的替代操作；
- 代理只能执行明确授权的最小动作；Ready、Merge、部署、迁移、删除和其他高风险操作的权限默认相互独立；
- 用户中断后必须停止；恢复时使用新的 `PROMPT_ID` 和新的授权，并先只读核验已完成、未完成与不确定状态；
- 高风险操作不得自动继续、自动恢复或重复执行状态不明的写动作。

完整执行规范见[高风险操作协议](../HIGH_RISK_OPERATION_PROTOCOL.md)。

## Consequences

- 高风险任务会增加一次明确授权交互，执行速度略慢；
- 审计性、可追溯性和用户可控性提高；
- 信息、SHA 或状态不完整时，任务会停止而不是推断；
- 未来所有 Mingecode 代理任务都必须遵守本决定和高风险操作协议；
- 其他仓库可以复用该协议，但本 ADR 只治理 Mingecode；
- 最终结果正确不能替代合规的授权与执行过程。
